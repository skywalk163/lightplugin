## 二、先前的「Z 大幅回退」是部署缺口，不是语言回退

修复前在同一台 0.88 上跑出的数字是 **Z_跑通 0.467（全量）/ 0.531（抽样）**，当时误判为语言回退。逐一复现探针后定位到 **两个部署缺口**，均与语言本体无关：

### 缺口 1：`light-merge/stdlib` 未打包上传（主因）

- 现象：大量模块报 `cannot import name '字符转ASCII' from 'stdlib.lightpub.字符串处理'`。
- 根因：`light-merge/src/code_generator.py:_resolve_lightpub_import()` 在**编译期**探测
  `LIGHT_MERGE/src/../stdlib` 根目录是否已有同名 `.py/.light`：
  - 有 → 走根目录完整版（如 `stdlib/字符串处理.py`，含 `字符转ASCII/URL编码/截取` 等）；
  - 无 → 改道 `stdlib.lightpub.字符串处理`（P2 桥接版，API 更窄，**没有**这些符号）。
- 打包时只带了 `light-merge/{src,antlrparser,cli}`，漏了 `stdlib`（9.2M / 排除缓存 3.5M、249 文件）。
- 结果：0.88 上所有 P1/P2 包被静默改道到窄版桥接模块，`模块未找到`/`无该属性` 成片出现。
- 验证：补传 `light-merge/stdlib` 后，`从 字符串处理 导入 字符转ASCII URL编码` 探针立即 `IMPORT_OK`。

### 缺口 2：`lightplugin` 只传了 `数据集/`，缺 `集成/` 与 `插件/`

- 现象：`设置页` 模块探针报 `模块未找到`，错误链指向第 44 行 `从 生产挂载 导入 挂载全部插件`。
- 根因：依赖链 `设置页 → 设置页深化 → 总入口:44 → 从 生产挂载 导入 挂载全部插件`，
  而 `生产挂载.light` 位于 `lightplugin/集成/`，0.88 上 lightplugin 目录只有 `数据集/`。
- 验证：补传完整 `lightplugin`（6.7M / 490 文件，含 `集成/` 与 75 个插件目录）后，`设置页` 探针 `IMPORT_OK`。
