# 存储抽象 · 复刻任务卡

- **对标 dsh**：`packages/storage`
- **能力**：键值/对象存储抽象：命名空间 + 读写删 + 多后端适配（内存/文件）
- **缺口核验**：完全无（存储 0 命中）；lightharness 无存储抽象层
- **优先级**：P5　**批次**：第 7 批　**状态**：pending
- **依赖**：无
- **挂接契约**：`造工具定义(名字, 描述, 参数, 执行函数, ...)` + `工具注册表`；需宿主服务时用 `绳构造注册` / `绳装配`

## 复刻记录

- **挂接**：`造工具定义` → `工具注册表`；暴露 4 个工具：`存储写入` / `存储读取` / `存储列举` / `存储删除`（命名空间=桶）。
- **验证**：`测试_存储抽象.light` 9 组全过（内存写入/读取/列举/删除、缺失键反例、文件后端切换+注入式内存字典模拟 I/O、未注入文件后端写入失败、挂载端到端、空命名空间反例、缺失键工具报错）。
- **踩坑**：`字典.弹出(键)` 是**实例方法**（`子.弹出(键)`），不能写成 `字典.弹出(子,键)`（类型对象无此方法，报「名称错误: 字典」）。
- **已知缺口（如实）**：
  - 文件后端真实磁盘 I/O 由宿主注入（读器/写器/列举器/删除器），本插件不内置文件系统栈；测试用内存字典模拟。
  - 文件后端下「读缺失键」与「键值为空字符串」无法区分（读器统一返回 空），缺失判定仅在内存后端严格成立；真实远端应让读器以哨兵区分。
  - 不做并发/持久化语义，单进程内存字典 + 注入式后端，对标 dsh 的存储抽象接口而非其分布式能力。
