## 复刻记录

- **挂接**：`造工具定义` → `工具注册表`；暴露工具 `装配团队面板`。
- **与兄弟插件的关系**：**不重造分派**。成员名单优先取注入的数据源；未配置数据源时
  **回退直读 代理团队 的注册成员**（`列出成员` + `取成员`），并把 `汇总团队结果()` 的
  派单/成功计数带进面板。边界：代理团队 是运行时（派给谁），本插件是 UI 状态（怎么显示）。
- **内核**：`配置数据源(源)`（签名 `() -> {"成员":[{"名字","状态"}], "消息":[{"序号","成员","内容"}]}`）、
  `追加消息(成员, 内容)`（无数据源时的自持消息流）、`取团队成员` / `取团队消息`、
  `按序排消息(表)`（按序号升序的选择排序，保证界面按时间序）、`装配成员面板`（选中者加 `*` 前缀）、
  `装配消息流`（`成员:内容` 换行拼接，空则「（暂无消息）」）、`选中(名字)` / `取选中`、
  `装配团队面板`（成员面板 + 消息流 + 选中 + 成员数 + 消息数 + 就绪 + 派单数 + 成功数）、`清空界面`。
- **验证**：`测试_团队界面.light` 15 组全过 —— 空团队反例（就绪=假、成员数 0、消息流提示暂无消息、
  空团队下选中失败）、数据源注入与回读、**乱序消息按序号排序**（1/2/3/4）、
  消息流按时间序拼接为 `甲:开工\n乙:收到\n甲:完成\n丙:归档`、成员面板「名字[状态]」、
  选中态切换（`*` 前缀）、选中不存在成员反例且不改原选中态、传空串取消选中、
  无数据源时回退读 代理团队 成员、追加消息按时间序拼接、与 代理团队 派单联动（派单数/成功数=1）、
  清空界面归零（L-166 回归）、以及「挂载进注册表后取出工具执行」的端到端
  （含选中不存在成员报错、空团队装配报错两条反例）。
- **踩坑**：本次无新增光明缺陷。沿用既有约束：`全局 X。` 写在段首；嵌套容器先取局部变量再改；
  循环变量 `甲/乙` 在 `按序排消息` 中只作下标，不与被调用函数同名。
- **已知缺口（如实）**：
  - 消息排序为 O(n²) 选择排序，且**只按整数字号**排序，没有真实时间戳（无墙上时钟依赖是有意取舍）。
  - 面板是**一次性快照**，不支持增量 diff / 订阅推送 / 虚拟滚动；成员状态不做轮询刷新。
  - 选中态**只存单个成员名**，不支持多选、不支持按消息定位选中。
  - 数据源与自持消息表是「二选一」关系（有数据源时 `追加消息` 不进面板），不做合并去重。
  - 无任何真实渲染/布局/主题；本插件只产出可断言的字符串与列表，不产出 HTML/组件树。
