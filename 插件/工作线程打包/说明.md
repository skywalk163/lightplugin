## 复刻记录

### 挂接方式

- 复用 `工具.light` 的 `造工具定义` / `造工具结果`；导出 `挂载(注册表)` 注册工具名 **`工作线程打包`**。
- 跨模块导入：`从 字符串处理 导入 子串位置`、`从 内置核心字典 导入 字典键列表`（须显式，见 LP-D-002）。
- 依赖标注 `工作线程运行时`，但本插件为**自包含纯逻辑**（依赖图/拓扑/overlay 校验），不实际导入它；依赖关系仅为语义归类。

### 设计：相对 dsh 的有意差异

dsh 真实打包器做「仓库扫描 + npm 发布视图 + 可达性 sweep + gzip tar」。
本复刻版只复刻**纯逻辑核心**：依赖图 → 拓扑序（Kahn）+ 循环检测 + overlay 挂载点校验（限定在 `home/` 与 `workspace/` 之下，对齐 dsh VFS 约束）。真实扫描由宿主注入「扫描器」，本模块只吃已给出的依赖表。

### 踩到的坑

1. **list/dict 类型混用（自查，非语言缺陷）**：`设 模块表 为 []` / `设 overlay表 为 []` / `设 入度 为 []` 三处都做 dict 下标（`模块表[名字] 为 ...` / `overlay表[文件] 为 ...` / `入度[名] 为 ...`）→ 类型错。修：三处全改为 `{}`。
2. **测试笔误（自查，非语言缺陷）**：测试第 75 行 `断言True_isError(定义["execute"](参坏))` 把整字典（造工具结果）传给只认布尔的 `断言True_isError` → 抛「应为报错」。修：取 `定义["execute"](参坏)["isError"]`（同文件第 73 行已正确取键）。

### 验证结果

`测试_工作线程打包.light` **全部通过**：拓扑序（a←b←c 顺序校验）/ overlay 合法性（`etc/` 下挂载点被拒）/ 装配（图就绪 + overlays）/ 循环检测（x↔y 环，装配失败）/ 挂载与工具（环图下装配工具报错 + 未知动作报错）。

### 已知缺口（如实）

- **不做真实仓库扫描 / npm 发布视图 / gzip tar**：只吃已给出的依赖表。
- **overlay 只校验挂载点前缀**：不校验源文件是否存在、不校验环路外的文件可达性。
- **拓扑序为 Kahn 入度法**：不输出关键路径 / 并行分层建议。
