## 复刻记录

### 挂接方式

- 复用 `工具.light` 的 `造工具定义` / `造工具结果`；导出 `挂载(注册表)` 注册工具名 **`工作线程运行时`**。
- 跨模块导入：`从 字符串处理 导入 子串位置`（须显式，见 LP-D-002）。

### 设计：相对 dsh 的有意差异

dsh 真实运行时是「整棵插件树跑在 Web Worker 里 + VFS 挂载 + 模块加载器 + 进程 shim」。
本复刻版只复刻**调度语义**：任务队列、按类型路由处理器、生命周期（空闲/忙碌/已停止）。真实隧道/传输由宿主注入，不碰浏览器、不碰 WebSocket。

### 踩到的坑

1. **LP-D-008（实踩）**：`全局 队列.`（半角句号）意图声明模块级可变队列，解析器把 `.` 当成员访问 → 报「期望成员名，但得到「\n」」。修：`全局 队列。`（全角句号）。见 LP-D-008。
2. **list/dict 类型混用（自查，非语言缺陷）**：最初 `设 处理表 为 []` 却做 `处理表[类型] 为 处理器`（dict 下标）→ 类型错。修：`设 处理表 为 {}`。
3. **队列"只追加 + 头指针"模式**：为避开 `全局` 的坑，队列名字 `队列` 绝不重绑（元素赋值共享即可）；仅在 `强制终止`/`重启` 清空处用 `全局 队列。` + `队列 为 []`。

### 验证结果

`测试_工作线程运行时.light` **全部通过**：注册处理器 / 提交任务（已停止状态拒绝提交）/ 派发（未知类型分支 + 正常派发）/ 队列长 / 停止·强制终止·重启（清空队列 + 重置头指针）/ 挂载与工具（未知动作报错）。

### 已知缺口（如实）

- **不接真实浏览器 / WebSocket / VFS**：不做跨 Worker 序列化，处理器为本地纯函数。
- **无并发**：单线程派发，不做真实进程 shim / 多 Worker 负载。
- **生命周期不含出错重试**：派发失败只返回原因，不自动重排。
