## 复刻记录

- **挂接**：暴露 3 个工具：`压缩评估` / `压缩选块` / `压缩摘要`。
- **验证**：`测试_上下文压缩.light` 13 组全过 —— 评估（块数 / 总用量 / 超预算）、旧优先选块（前缀累计）、新优先选块（后缀累计）、预算极小保留 0 块、摘要（全部 / 指定保留 / 截断）、注入定额计量器后用量变化、撤掉注入后回到字符数、状态表登记、空内容登记反例、挂载端到端、预算 0 反例、空块列表反例。
- **实现要点**：
  - 块的「标识」缺失时用序号兜底；「内容」缺失时按空串（用量 0）处理。
  - 选块判据：旧优先 = **前缀累计**（从最早块累加到当前块）≤ 预算；新优先 = **后缀累计**（从当前块累加到最新块）≤ 预算。光明侧无内置 reversed，故用「总量 − 前缀 + 当前」算出后缀，避免倒序遍历。
  - 「显式传空块列表」= 真的没有块，**不回退**到宿主登记表；只有**没传**参数时才回退。
- **踩坑**：schema 描述里写 `每项 {标识, 内容}` → 光明把字符串里的 `{...}` 当插值，编译期直接 `名称错误: name '标识' is not defined`（属既有 LP-D-001 花括号插值问题）。已把描述改成不含花括号的写法。
- **已知缺口（如实）**：
  - 未注入计量器时 token 数 = **字符数**（对中文偏保守、对英文偏乐观），不是真 token。
  - 摘要是**截断**而非语义压缩（不做 LLM 摘要），只保证长度可控。
  - 无「必须保留块 / 钉住块」概念（dsh 的 compaction 有 pinned blocks）。
