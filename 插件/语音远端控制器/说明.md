## 复刻记录（R101 任务线 A，2026-09）

### 与 #13 的关系（本轮认知修正）

#13 语音转文字 是**模型工具层的异步作业编排**（长音频分段 + 作业轮询）；
本插件是 **Web Remote 入站校验与限流层**（SpeechController，服务端控制器）。
两者**通过注入的识别器契约对接**：dsh 里 api-speech-to-text 依赖
speech-to-text 的 `ctx.speechToText`（resolve/transcribe/snapshot/follow/configure/prepare/
cancelPreparation），自己只做「入站校验 + 限流 + 错误码包装」。
`api-speech-to-text 不是第三种 ASR 后端`（#13 旧说明的「三包合一」表述有误，由 M 线修正）。

### 上游锚点与逐段对齐

- 对标 `G:\github\deepseek-harness\packages\experimental\api-speech-to-text\src\index.ts`（110 行）+ `types.ts`，
  上游锚点 e5b5ccbfcb（0.2.0-rc.1）；WAV 校验读 `speech-to-text\src\wave.ts`（23 行）。
- `配置形状默认(覆盖)` ← Config zod（maxAudioBytes 默认 4*1024*1024 / 下限 46；
  maxDurationSeconds 默认 120 / 下限 1；zod 拒绝语义投影为抛中文错）。
- `校验WAV(字节, 最大秒数)` ← wave.ts 逐段投影：RIFF/WAVE/fmt␣/data 块名、fmt 体
  （16/PCM/单声道/16000/32000/2/16）、RIFF 块长=总长-8、data 块长=总长-44、数据偶对齐、
  时长 = (总长-44)/32000 超限抛错；文案保留「16kHz 单声道 PCM16」。
- `转写请求(请求, 配置, 信号被中止, 识别转写)` ← transcribe 校验链逐段对齐 index.ts:88-109：
  ① 入口 `信号被中止()` 先抛（try 之外，不包装）；② base64 长度预检
  `len > ceil(maxAudioBytes/3)*4` → `speech/invalid-audio（reason=encoding-or-size）`；
  ③ canonical round-trip（解码后重编码逐字相等）；④ 解码字节数 > maxAudioBytes 抛超限；
  ⑤ 调 `校验WAV`；⑥ 调注入 `识别转写(音频字节, providerId, language)` -> 稿本；
  ⑦ try 内任何错误包装为 `speech/transcription-failed: <原因>`；包装前若 `信号被中止()` 为真则
  透抛原始错误（对齐 catch 里的 `signal.throwIfAborted()`）。
- `目录快照(识别器快照, 配置)` ← catalog 的 `{ ...snapshot, ...config }`：浅拷贝快照后写配置
  限额（配置后写，同名键覆盖），不改注入的快照字典。
- `follow` / `configure` / `prepare` / `cancelPreparation` ← 同名薄转发段落，全部调注入字典里的
  同名函数，不自建状态机（dsh 侧也是薄转发，无新逻辑）。
- `挂载(注册表, 识别器通道)` ← Remote 服务装配投影：把 `speechController.catalog` /
  `speechController.transcribe` 经 `绳构造注册` 注册进绳表；测试用 `绳装配(取目录钩子)` 走通
  归一可见。**这是 lightplugin 首个走通 `从 toolcordis 导入` 跨域绳挂载的插件**。
- base64 编解码（`音频解码` / `音频编码`）为纯逻辑实现（RFC 4648 + 严格 padding），投影
  `Buffer.from(encoded,'base64')`（宽松解码：跳过字母表外字符）与 `toString('base64')`
  （严格 canonical 编码）；二者组合支撑 round-trip 检查。

### 注入契约（宿主绑定投影）

| dsh 宿主绑定 | 光明投影 |
|---|---|
| AbortSignal.throwIfAborted | 入参 `信号被中止()` -> 真假 |
| ctx.speechToText.resolve + transcribe | 入参 `识别转写(音频字节, 提供者, 语言) -> 稿本` |
| ctx.speechToText.snapshot | 入参 `识别器快照()` -> 字典 |
| ctx.speechToText.follow/configure/prepare/cancelPreparation | 通道字典同名键 |
| Buffer | 整数列表（0..255）；base64 编解码为纯函数 |
| zod Config | `配置形状默认(覆盖)` |
| RemoteError | 错误消息前缀 `speech/invalid-audio` / `speech/transcription-failed` |

### 已知缺口（如实）

- **无 typert 流协议**：`follow` 的 AsyncIterable 分帧属宿主协议，投影为一次性调用注入函数返回流帧。
- **RemoteError 无结构化 details**：dsh 的 `{ reason: ... }` details 字典投影进错误消息文本
  （`reason=encoding-or-size` / 原因内嵌），无独立字段。
- **字节是整数列表**：非真实 Buffer/TypedArray；base64 编解码为 O(n) 纯逻辑，宿主接真实大音频时
  应换原生实现。
- **prepare 的 SpeechPreparationOptions 未深校验**：dsh 侧由 provider 校验，注入承接，本层不复制。
- **挂载只登记绳清单**：真实 Web Remote 通道注册（typert namespace `speech`）属宿主接线，不移植。
