- **能力**：平列表待办项：新增 / 完成 / 列出（可只看未完成）/ 删除，带优先级
- **缺口核验**：dsh 有 `packages/todo` 包；lightharness 侧只有内部 `待办.light`，**未以 `造工具定义` 注册成模型可调用工具** → 广度缺口，本插件补门面
- **优先级**：P2　**批次**：第 11 批　**状态**：done

- **挂接契约**：`造工具定义(名字, 描述, 参数, 执行函数, ...)` + `工具注册表`

## 边界：不要重复造轮子

## 复刻记录

- **挂接**：`造工具定义` → `工具注册表`；暴露 4 个工具：`待办添加` / `待办完成` / `待办列出` / `待办删除`。
- **验证**：`测试_待办清单.light` 8 组全过 —— 添加与列出、只列未完成、完成一条后计数变化、删除、空标题返回 -1、完成/删除不存在编号失败、挂载端到端（注册表 execute 调用）、空标题工具报错。
- **实现要点**：
  - 内存表 `id -> {标题, 完成, 优先级, 序}`，id 为自增整数的字符串形式，与 dsh 的平列表语义对齐。
  - 「列出」返回**人类可读行列表**（`"[1] 标题 (优先级=高) [已完成]"`），便于模型直接消费；不返回裸字典（光明侧字典转字符串不可控）。
  - 持久化走 `注入持久化(写, 读)`，测试不注入 → 零磁盘 I/O。
- **踩坑**：无新增（沿用既有：模块级 `下一号` 必须 `全局 下一号。` 才能自增）。
- **已知缺口（如实）**：
  - 不做优先级排序（只记录、不排序），dsh 侧亦为插入序。
  - 无持久化实现本体：真实磁盘落盘由宿主注入，未注入即纯内存，进程退出即失。
  - 无多会话 / 多用户隔离：单进程单表。
