# 打包分发 · 复刻任务卡

- **对标 dsh**：`packages/bundle`
- **能力**：打包分发：产物清单合并/依赖收集/版本登记，注入式打包器
- **缺口核验**：完全无（bundle 0 命中）
- **优先级**：P8　**批次**：第 9 批　**状态**：pending
- **依赖**：无
- **挂接契约**：`造工具定义(名字, 描述, 参数, 执行函数, ...)` + `工具注册表`；需宿主服务时用 `绳构造注册` / `绳装配`

## 复刻记录

- **挂接**：`造工具定义` → `工具注册表`；暴露工具 `登记产物` / `生成清单`。
  入口段落 `挂载(注册表)` 返回 `真`。
- **注入式打包器**：`设置打包器(打包器)` / `执行打包(清单, 打包器)`；
  显式传入的打包器优先于默认打包器，未注入时返回 `["ok": 假, "原因": "未注入打包器"]`，
  且 `生成清单` 工具在未注入打包器时**降级为只返回清单本身**（不报错）。
- **验证**：`测试_打包分发.light` 13 组全过（参数校验反例、依赖保序去重、同名覆盖登记、
  版本登记与刷新、跨产物依赖收集、清单合并与摘要、移除产物、未注入打包器反例、
  注入后调用计数、以及"挂载进注册表后取出工具执行"的端到端）。
  运行：`python 运行.py 插件/打包分发/测试_打包分发.light` → 输出「测试_打包分发 全部通过」。
- **已知缺口（如实）**：
  - **不做真实打包**：不打 tarball / zip、不落盘、不算校验和，打包动作全部委托注入的打包器。
  - **版本登记只是同名覆盖**，不解析 semver、不做版本冲突检测与依赖版本收敛
    （dsh 侧的 lockfile/依赖解析图未复刻）。
  - **依赖以逗号分隔字符串入参**，不支持嵌套依赖树与循环依赖检测。
  - 产物表与版本表是**进程内字典**：无持久化、无并发加锁。
  - 未做产物体积统计、增量打包与缓存。
