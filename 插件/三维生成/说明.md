## 复刻记录

### 挂接方式

- `从 异步作业轮询 导入 提交作业, 查询作业, 完成作业, 轮询直到终态`（复用 P0-1 底座，不重实现）
- `从 工具 导入 造工具定义, 造工具结果`；`挂载(注册表, 建模器=空)` 注册工具名 **`三维生成`**
- 建模器签名 `(提示词, 格式, 精度) -> ["完成": 真假, "资产": 地址, "原因": 说明]`，
  由宿主注入真实文生 3D 服务；测试注入确定性建模器 → 零网络、零计时 flaky。

### 与图片生成的差异（不是无脑复制）

图片是单参数域（尺寸），三维是**双正交参数域**：
`格式`（glb/obj/usdz，影响产物后缀与下游可用性）+ `精度`（低/中/高，影响耗时与计费）。
因此校验拆成 `有效格式` / `有效精度` 两个独立段落，宿主可按需只收紧其一。

### 验证结果

`测试_三维生成.light` **9 组全部通过**（本机 `运行.py`，一次跑通、零返工）：

1. 两参数域校验正反例（含 fbx / 极高 两个反例）
2. 提交作业（作业名 `三维生成`、初始状态 `待处理`）
3. 三类非法参数都不产生作业（空提示词 / 非法格式 / 非法精度）
4. 生成立即完成 → 终态 `成功`
5. 多轮才完成 → 建模器被推进 ≥3 次
6. 永不推进 → `轮询超时`
7. 参数不合法时不进入轮询（`轮次 == 0`）
8. **参数透传探针**：格式 `usdz`、精度 `高` 原样送达建模器，且只调用 1 次
9. 挂载 + `定义["execute"]` 端到端；未绑定建模器时工具明确报错

### 踩到的坑

本插件**未遇到新的语言缺陷**（LP-D-001~004 的规避做法已成为肌肉记忆，实现阶段一次成型）。
唯一的返工是自己写错断言（段数数错），非语言问题。

### 已知缺口（如实，不谎报对齐度）

- **不内置任何真实建模服务**：只定义契约与装配流程，宿主必须自行注入建模器。
- **参数白名单静态写死**：`glb/obj/usdz`、`低/中/高` 未配置化，宿主换供应商需改源码。
- **不支持失败态回填**：`失败作业` 已导入但未使用——建模器只回报"未完成"，无法表达
  "明确失败（如内容违规）"。真实服务需要区分"还在跑"和"彻底失败"，本版未做。
- **无产物校验**：拿到的资产地址不验证可达性、不校验格式后缀与请求格式是否一致。
