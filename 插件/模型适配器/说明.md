# 模型适配器 · 复刻任务卡

- **对标 dsh**：`packages/llm`
- **能力**：模型适配器：多后端路由 + 请求构造/响应解析，注入式传输(模型名,消息)->回复
- **缺口核验**：完全无（llm 0 命中）；lightharness 无模型请求层
- **优先级**：P7　**批次**：第 8 批　**状态**：pending
- **依赖**：无
- **挂接契约**：`造工具定义(名字, 描述, 参数, 执行函数, ...)` + `工具注册表`；需宿主服务时用 `绳构造注册` / `绳装配`

## 复刻记录

- **挂接**：`造工具定义` → `工具注册表`；暴露工具 `模型补全`。
  真实网络调用由注入式 `transport(模型名, 消息表) -> 回复文本` 提供
  （宿主接真实 HTTP/sdk，测试注入假 transport）。零网络、零墙上时钟。
- **验证**：`测试_模型适配器.light` 全过（路由判定 claude/gemini/openai、请求结构含模型名+消息角色/内容、
  双后端注入断言路由命中正确后端、空回复判失败、空消息反例、未知后端/未知模型反例、挂载端到端 共 12 组断言）。
- **踩坑**：transport 契约签名固定为 `(模型名, 消息表)`，与 `模型补全核心` 调用一致（不要多加后端参数）；
  路由启发式用 `子串位置(模型名, "claude") >= 0`（需 `从 字符串处理 导入 子串位置`），
  避免 `.以开头`/`.以结尾` 方法；`items` 子 schema 先赋变量再嵌进属性表。
- **已知缺口（如实）**：
  - 路由为模型名子串启发式（claude/gemini → 对应后端，其它 → openai），非 dsh 的完整供应商注册表；
    未注册后端直接判失败（即「未知模型/未知后端」反例的语义来源）。
  - 仅做请求构造 + 响应解析（空回复判失败），不含 dsh 的流式/工具调用/多轮上下文管理。
  - 多后端 transport 各自独立注入，本插件不内置任何真实 HTTP 客户端。
