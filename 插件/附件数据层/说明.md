# 附件数据层 · 复刻任务卡

- **对标 dsh**：`packages/attachment`
- **能力**：附件数据层：上传/下载/列举 + 格式归一（文本/二进制），注入式存储后端
- **缺口核验**：完全无；附件准入.light 只做准入判定，本插件做数据搬运与格式归一
- **优先级**：P6　**批次**：第 8 批　**状态**：pending
- **依赖**：无
- **挂接契约**：`造工具定义(名字, 描述, 参数, 执行函数, ...)` + `工具注册表`；需宿主服务时用 `绳构造注册` / `绳装配`

## 复刻记录

- **挂接**：`造工具定义` → `工具注册表`；暴露工具 `附件上传` / `附件下载` / `附件列举`（共 3 个）。
- **架构**：存储后端为注入式（模块级 `后端上传/后端下载/后端列举` 三函数，由 `注入后端()` 设置；
  默认挂内存实现 `内存上传/内存下载/内存列举`，零网络、零磁盘、确定性）。`附件上传处理` 经
  `归一格式()` 把格式强制归一为 `文本`/`二进制` 两类（其它任意值归一成 `文本`）。
  严格守边界：不做任何准入判定（大小/类型白名单等由 附件准入.light 负责）。
- **验证**：`测试_附件数据层.light` 全绿（格式归一三态、上传→下载往返、fake 后端落盘断言、
  下载不存在反例、列举含关键字过滤、经注册表执行流水线触发 schema 缺字段拒绝）。
- **踩坑**：`跳出` 在 光明 里是「break」而非「continue」，列举过滤里误用会提前终止循环
  → 改用命中标志位；
  `execute` 直调会绕过 schema 校验，缺字段反例必须走 `注册表.执行(名字, 原始JSON)` 才会触发
  `PARAM_SCHEMA_INVALID`。
- **已知缺口（如实）**：
  - 格式归一只认 `文本`/`二进制` 两类，无 MIME 细分；二进制内容以字符串形式承载（不做真实字节编码）。
  - 真实磁盘/对象存储后端由宿主注入，本插件不内置任何 I/O 栈。
  - 内存后端为进程内单例，无持久化、无容量上限（仅用于单测与宿主默认占位）。
