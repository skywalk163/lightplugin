# 运行时诊断 · 复刻任务卡

- **能力**：运行时诊断采集：指标快照/异常捕获上报/健康检查，注入式采集器
- **缺口核验**：完全无（runtime-diagnostics 0 命中）
- **优先级**：P7　**批次**：第 8 批　**状态**：pending
- **依赖**：无
- **挂接契约**：`造工具定义(名字, 描述, 参数, 执行函数, ...)` + `工具注册表`；需宿主服务时用 `绳构造注册` / `绳装配`

## 复刻记录

- **挂接**：`造工具定义` → `工具注册表`；暴露工具 `采集诊断快照`、`健康检查`。
  核心逻辑纯函数；真实采集由宿主注入的「采集器」「探针表」提供（模块级 `诊断状态`
  字典承载，测试注入确定性 fake），零网络、零墙上时钟。
- **验证**：`测试_运行时诊断.light` 全绿（正常快照结构、采集器抛错被隔离不崩溃、
  健康检查聚合、探针抛错隔离、显式异常上报计数、挂载端到端、缺参 schema 反例）。
- **踩坑**：模块级 `全局 X。` 只能写在 段落 体内——模块级可变状态改用 dict 承载、
  函数内只对其字段赋值（不重绑名字），无需 `全局`；模块级 `设` 自顶向下求值，
  被引用的 段落 必须定义在前（把 `默认指标采集` 提到 `诊断状态` 赋值之前）。
- **已知缺口（如实）**：
  - 仅复刻「指标快照 / 异常捕获上报 / 健康检查聚合」三类纯逻辑；dsh 侧的实时采样线程、
    健康检查 HTTP 端点、结构化上报通道均依赖宿主注入，本插件不内置。
  - 健康检查为一次性快照聚合，不做持续轮询/历史趋势（与对标的 runtime-diagnostics 


  采集语义一致，但不含时序窗口）。
  - 指标字段集合为固定白名单（cpu/memory/线程数），未对接 dsh 的全指标注册表。
