## 复刻记录

### 挂接方式

- 复用 `工具.light` 的 `造工具定义` / `造工具结果`；导出 `挂载(注册表, 评审器=空)` 注册工具名 **`自动审查`**。
- 跨模块导入：`从 字符串处理 导入 子串位置`、`从 内置核心字典 导入 字典键列表`（均须显式，见 LP-D-002）。

### 设计：相对 dsh 的有意差异

dsh `auto-review` 直接接模型做语义评审；本复刻版把**确定性规则**抽出来先跑（这部分不需要模型，省钱且稳），语义评审作为**可选注入增强**（`绑定评审器` / `审查并增强`）。这是**有意设计差异**，不是能力缺失——把"能确定性判定"和"需要人/模型判断"分层。

确定性规则（只作用于**新增行**，删除/上下文行不要求清理）：
- `规则_空改动`：纯空白/空行新增 → 提示
- `规则_未挂人标记`：TODO → 警告；FIXME → **阻断**
- `规则_调试残留`：`console.log` → 警告；`print(` → 提示（仅新增行）
- `规则_超长行`：长度 > 阈值 → 提示

### 踩到的坑

- **LP-D-002**：`字符串处理` / `内置核心字典` 的模块函数必须显式导入，不自动可见。
- **LP-D-006**：禁止行尾「+」续行，多行一律用分步 `设 X 为 X + ...`。
- **测试笔误（非语言问题）**：超长行阈值初设 20，但那行中文仅 18 字符不触发 → 改 10 通过。已在测试注释里标明，避免下次误判为语言缺陷。

### 验证结果

`测试_自动审查.light` **11 组全部通过**（一次跑通，仅测试笔误已修）：差异行解析（+/−/空格/未知）/ 统计 / 空差异无意见 / 干净改动零意见 / FIXME 阻断 / TODO 仅警告 / console.log+超长行 / 只对新增行跑规则（删除行不触发）/ 空改动检测 / 渲染与挂载（阻断项报错、注入语义评审器追加 1 条）。

### 已知缺口（如实）

- **不做语义评审**：除非宿主注入评审器，否则只覆盖确定性规则（6 条），不读真实业务语义。
- **不读真实文件**：只收差异行（每行以 +/−/空格开头），不做 AST/依赖图分析。
- **规则集小**：无安全检查（硬编码密钥、SQL 拼接等）、无覆盖率/复杂度类规则——按需可加。
- **未挂人标记只查字面 TODO/FIXME**：不接 issue 跟踪系统做真"挂单"校验。
