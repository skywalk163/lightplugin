# 扩展加载 · 复刻任务卡

- **对标 dsh**：`packages/extensions`
- **能力**：扩展加载运行时：清单解析/启用禁用/加载顺序/冲突检测
- **缺口核验**：完全无（extensions 0 命中）
- **优先级**：P6　**批次**：第 8 批　**状态**：pending
- **依赖**：无
- **挂接契约**：`造工具定义(名字, 描述, 参数, 执行函数, ...)` + `工具注册表`；需宿主服务时用 `绳构造注册` / `绳装配`

## 复刻记录

- **挂接**：`造工具定义` → `工具注册表`；暴露 2 个工具：
  `注册扩展` / `列出扩展`。扩展清单表为**注入式状态**（模块提供 `装载扩展清单(表)` 由宿主或测试注入），
  处理函数为纯逻辑，零磁盘、零进程；真实扩展的物理加载/激活由宿主负责（注入式，本插件不触碰 require/import）。
- **验证**：`测试_扩展加载.light` 全过（启用/禁用状态、加载顺序拓扑排序、缺失依赖反例、依赖未启用反例、互斥冲突反例、端到端注册后执行与列表明细）。
- **踩坑**：同 shell环境层——模块顶层不得写 `全局`，否则报「代码生成错误: 「全局」只能写在段落（函数）体内」。
- **已知缺口（如实）**：
  - 仅做**清单层纯逻辑**（登记/校验/排序/冲突判定）；物理激活、版本约束、优先级策略未覆盖。
  - 环依赖靠 `已访问` 标记截断防死循环，但**不显式报错环依赖**（与会沉默通过，仅顺序退化）。
  - 冲突判定为「与已启用扩展互斥即失败」的即时判定，未做全局求解（如整体依赖可行解）。
