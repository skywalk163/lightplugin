## 复刻记录

- **挂接**：`造工具定义` → `工具注册表`；暴露 1 个工具：`SSH执行`。真实传输由模块级注入式 `设定传输(函数)` 提供（宿主接真实 SSH 客户端，测试传真 成功/失败），handler 负责结果回收与失败处理（非零退出码 → 报错并附 stderr），实现零真实网络。
- **验证**：`测试_SSH远程执行.light` 全绿（退出码 0、含「全部通过」）。覆盖：配置归一（缺省端口 22、认证 密码）、端到端注册 `SSH执行`、成功路径结果结构 + handler 不报错、失败路径（退出码 1 + stderr 回收）、反例（未注入传输器 → 失败 -1 并提示）。
- **踩坑**：无光明语言级错误；复用既定注入模式（`设定传输` 与 网页抓取 `取字节器` / 异步作业轮询 `推进器` 同构），未触碰 light-merge/src。
- **已知缺口（如实）**：
  - 仅实现「单命令下发 + 结果回收」，未覆盖 dsh 的 多命令会话复用、scp/sftp 文件传输、端口转发、跳板机（ProxyJump）、交互式密码/二次认证提示。
  - 失败处理返回结构化 `{成功, 原因, 退出码, 标准输出, 标准错误}`，但 handler 把结果压成纯文本 content（光明 `造工具结果` 仅收字符串），结构化明细需宿主侧再解析。
  - 认证仅透传「密码/私钥」字段占位，真实凭据获取依赖宿主注入。
