## 复刻记录

### 挂接方式

- 复用 `工具.light` 的 `造工具定义` / `造工具结果`；导出统一入口 `挂载(注册表)` 注册工具名 **`语音打包`**。
- **跨域联动**：`从 语音输入前端 导入 取分片, 分片数`，`打包当前会话(会话号)` 直接拿前端当前录音会话的分片来装配，省去调用方搬运。

### 设计：为什么单独成一层

前端只知道「几个分片、各多少帧」；发送侧还要决定元信息怎么填、总字节多大、会不会超限、分片顺序/正性是否完整。这类「发送前校验 + 装配」放在前端会让状态机臃肿，放在转写侧又太晚。故独立一层，**不碰音频字节**（字节由宿主持有），只产出「负载描述 + 校验结论」，单测零设备依赖。

### 踩到的坑（含本批核心新坑）

- **LP-D-006（本轮核心新发现，直接来自本插件）**：`设 负载 为 "a" +` 行尾 `+` 接换行再接 `"b"` 续行时，编译器**静默使变量未绑定**，且诊断报在无关的后继行（原报错 `name '超限' is not defined` 指向后面才会用到的变量，极具误导性）。对照实验：裸赋值 / 分步拼接 / 括号内跨行均正常，唯独「行尾 `+` 续行」失效。修复：改为分步 `设 负载 为 负载 + "..."`。已写入 `语言缺陷反馈.md` 与报错数据集。
- **LP-D-002**：`从 字符串处理 导入 子串位置` 必须显式导入。
- **L-044 / L-047**：命名避开「文本」；字典字面量先赋变量。

### 验证结果

`测试_语音输入打包.light` **9 组全部通过**（一次跑通）：默认配置校验 / 元信息与字节估算（单/双声道、零帧）/ 分片统计+校验（空、含非正、坏序号定位）/ 装配负载正常（750 帧=1500 字节）/ 超限反例 / 非法分片不产出负载 / 跨域联动直接打包前端当前会话（3 片/25 帧/50 字节）/ 空会话反例 / 挂载与工具层（合法分片、非法分片反例）。

### 已知缺口（如实）

- **不碰字节**：`负载` 是 URL 风格 query string（`会话号.编码?采样率=…&帧数=…`），不是真实 multipart/form-data 上传体；字节由宿主持有并真正发送。
- **上限字节静态 10MB**，未配置化。
- **字节估算用每帧字节近似**：不区分真实采样率/编码的帧结构（如 wav 头部），只做 `帧数×每帧字节×声道`。
- **不分片重叠/不做端到端校验**：只校验分片正性与总数，不验证音频内容连续性。
